## Description

The `_persist_personas()` method in `src/services/workspace_pipeline.py` (lines 377-503) uses a destructive "delete all, then insert" strategy for replacing personas associated with a workspace. On line 473-475, it first executes `DELETE FROM persona WHERE workspace_id = ?` to remove all existing personas, and then on lines 478-497 it iterates over the new persona data and inserts each one individually via `self.db.add(Persona(...))`.

The critical problem is that these operations occur within the same transaction but without a savepoint. If the insertion loop fails partway through (e.g., due to a validation error, a database constraint violation, or an unexpected data format in one of the persona records), the deletion has already been flushed to the database. The caller `_persist_brand_voice_and_personas()` on line 362 calls `await self.db.commit()` after `_persist_personas()` returns, but if `_persist_personas()` raises an exception, the caller's `except` block on line 365 calls `await self.db.rollback()`, which rolls back the entire transaction including the brand voice changes — but only if the exception propagates cleanly.

According to SQLAlchemy 2.0 documentation on nested transactions, `session.begin_nested()` creates a `SAVEPOINT` in the database, allowing a subset of operations to be rolled back independently of the outer transaction. This is the standard pattern for making a "replace all" operation atomic: if the insertions fail, the savepoint rollback also undoes the deletion, preserving the original data.

The project uses `asyncpg>=0.30.0` and `sqlalchemy` (implicit, estimated 2.0.x based on the `select()` / `mapped_column` patterns used throughout), both of which fully support async savepoints via `async with session.begin_nested()`.

## Why This Matters (Context & Reasoning)

Personas are generated by an LLM pipeline (`workspace_pipeline.py`) that scrapes a website, analyzes the content, and extracts author/expert personas. This process is expensive (it involves web scraping, LLM calls, and parsing structured output). If the pipeline generates 5 new personas from a website refresh, but the 3rd persona insertion fails due to bad data, the user loses all their existing personas AND only gets 2 of the 5 new ones — or none at all if the rollback covers everything.

The persona data comes from LLM structured output which is inherently unpredictable. Field values like `linkedin_url` could contain invalid data, `name` could be excessively long, or the `areas_of_expertise` field could be in an unexpected format. Any of these could cause a database constraint violation during insertion.

The workspace pipeline runs as a background task (via `asyncio.create_task` in `workspace_service.py:163`), so failures are already somewhat invisible (see TASK-093). Combined with the data loss risk, this makes the delete-then-insert pattern particularly dangerous.

---

## Impact

- **Severity:** Partial failure during persona insertion leads to complete data loss of all personas for that workspace. Users would need to re-run the entire brand voice extraction pipeline to recover their personas.
- **Affected Users/Flows:** Any workspace that runs the brand voice extraction pipeline (workspace creation, manual brand voice refresh). Affects the persona display on workspace settings and the persona selection during content creation.
- **Blast Radius:** Isolated to the persona data for the affected workspace. Does not affect other workspaces or other data types.

## Recommended Solution

### Step 1: Wrap the delete-and-insert in a savepoint using `begin_nested()`

```python
# File: src/services/workspace_pipeline.py
# Replace lines 469-503 (the delete-insert block inside _persist_personas) with:

        from sqlalchemy import delete
        from src.api.models.knowledge_models.persona_model import Persona

        # Use a savepoint to make the delete-then-insert atomic.
        # If insertion fails, the savepoint rollback also undoes the deletion,
        # preserving the original personas.
        async with self.db.begin_nested():
            # Delete existing personas for this workspace
            await self.db.execute(
                delete(Persona).where(Persona.workspace_id == self.workspace_id)
            )

            # Insert new personas with ALL fields
            for persona_data in personas_data:
                persona = Persona(
                    workspace_id=self.workspace_id,
                    # Basic fields
                    name=persona_data.get("name"),
                    description=persona_data.get("description"),
                    # E-E-A-T Professional fields
                    full_name=persona_data.get("full_name"),
                    professional_title=persona_data.get("professional_title"),
                    areas_of_expertise=persona_data.get("areas_of_expertise"),
                    tone_of_voice=persona_data.get("tone_of_voice"),
                    bio=persona_data.get("bio"),
                    linkedin_url=persona_data.get("linkedin_url"),
                    # User persona fields
                    demographics=persona_data.get("demographics"),
                    pain_points=persona_data.get("pain_points"),
                    goals=persona_data.get("goals"),
                    behaviors=persona_data.get("behaviors"),
                )
                self.db.add(persona)

            # Flush within the savepoint to detect constraint violations
            await self.db.flush()

        logger.info(
            f"Persisted {len(personas_data)} persona(s)",
            extra={"workspace_id": str(self.workspace_id), "operation_id": self.operation_id}
        )
```
